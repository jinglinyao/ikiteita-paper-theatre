# 复刻指南（写给 ChatGPT、Trae 等能操作电脑的智能体）

> 读者：在用户的 Windows 电脑上有终端权限的 AI 智能体。
> 目标：从这个仓库出发，搭好环境，渲出与原作一致的《显像管的外侧》成片（2560×1440，24 fps，197.6 秒，4742 帧）。
> 设计依据：同目录的 [`显像管的外侧_设计图纸.jpg`](显像管的外侧_设计图纸.jpg)（超长图）。

---

## 0. 先读这几条规矩

1. **歌曲和歌词不在仓库里，也不许你去网上找。** あいみょん《生きていたんだよな》受版权保护。向用户要：
   - 音频文件 → 放到 `audio/song.wav`；
   - 可选的歌词与译文 → 按 `docs/字幕_待填.json` 的格式填好，另存为 `docs/字幕.json`。
   用户不给歌词也能出片，只是没有字幕。
2. **只在 Windows 10/11 上做。** 脚本用 Git Bash 运行，字幕要用 Windows 自带的微软雅黑和 Segoe UI。
3. **Unity 的登录和许可证激活由用户本人完成。** 你不要输入用户的账号和密码。
4. **不需要任何 API Key。** AI 生成的视频、图片和三维头都已经在仓库里。`tools/gen_ali.py`、`tools/gen_art.py` 只在想重新生成时才用。
5. **路径里不要有空格。** 仓库要克隆到不含空格的路径，比如 `D:/work/ikiteita-paper-theatre`；中文路径也尽量避免。
6. **每一步都按“验收”核对。** 不通过就停下，把现象和日志告诉用户，不要跳步。

## 2. 取得代码并准备

在 **Git Bash** 里执行：

```bash
git clone https://github.com/jinglinyao/ikiteita-paper-theatre.git /d/work/ikiteita-paper-theatre
cd /d/work/ikiteita-paper-theatre
python -P tools/setup_paths.py        # 把脚本里作者机器上的 E:/sucai/ikiteita 改成你的克隆路径
python -P tools/fetch_fonts.py        # 下载字幕、片名、封面用的开源字体到 fonts/
```

**验收**：
- `setup_paths.py` 打印 `changed N files`，N 在 10 以上；
- `fetch_fonts.py` 最后打印 `failed: 0`。

然后放歌曲（向用户要）：

```bash
ffprobe -v error -show_entries format=duration -of csv=p=0 audio/song.wav
```

**验收**：时长是 193.09 秒左右（±0.05）。原作用的是 44.1 kHz、16 位、立体声 WAV。时长对不上，说明版本不同，整片的小节表会错位，**要停下来问用户**。

## 3. 打开 Unity 工程

```bash
unity open "$(pwd -W)/unity"
unity status --until-ready --project-path "$(pwd -W)/unity" --timeout 1800
```

- 第一次打开会导入约 500 MB 资源、下载 UniVRM 和 uLipSync，要 10–30 分钟。
- 包清单里已经有 `com.unity.pipeline`，Unity CLI 用它驱动编辑器。

**验收**：
- `unity status` 的 state 是 `ready`；
- 没有 Safe Mode；`unity status --format json` 里没有 `safeMode.compileErrors`。

有编译错误时，先看 `unity status` 列出的错误，常见原因是包没下载完（网络问题）。

再确认场景能被脚本驱动：

```bash
bash tools/sets.sh Open '["stage"]'
```

**验收**：输出 `result: opened stage`。

## 4. 渲染（一条命令）

```bash
bash tools/render_all.sh 成片 cut tv
```

它按顺序做五件事，下面是在 RTX 4060 级别显卡上的参考耗时：

| 步骤 | 内容 | 产物 | 参考耗时 |
|---|---|---|---|
| 1 | 从电视正面机位把整部片渲一遍（1440×1080，4634 帧） | `unity/Capture/tv_raw/` | 25–40 分钟 |
| 2 | 把三段 AI 视频写进电视开头 14 秒（`tools/tv_clips.py`） | `unity/Capture/tv/` | 1 分钟 |
| 3 | 播放模式里逐镜头渲舞台（70 个镜头，前后各留 8 帧，约 5900 帧） | `unity/Capture/cut/Snn/` | 30–60 分钟 |
| 4 | 房间镜头（11 个），电视屏幕贴上第 2 步的画面 | `unity/Capture/cut/Snn/` | 10–20 分钟 |
| 5 | 合成：软切、叠化、片名、撕裂、字幕、片尾、响度 −14 LUFS | `deliver/film/成片.mp4` | 60–100 分钟 |

**注意**：
- 渲染时**不要让编辑器窗口最小化**，也不要锁屏。编辑器不在前台时，播放模式可能停在第一帧（表现为帧数不再增长）。
- `render_all.sh` 发现帧数长时间不涨会自动停下。这时让用户把 Unity 窗口切到前台，再单独重跑那一步（命令见第 5 节）。
- 第 5 步是 CPU 密集型，一帧约 1.1 秒。

**验收**：
- 合成最后一行是 `missing frames by shot: none`；
- 最后打印的时长是 `197.6`；
- 再跑一次 `ffprobe -v error -count_frames -select_streams v:0 -show_entries stream=nb_read_frames -of csv=p=0 deliver/film/成片.mp4`，结果是 **4742**。

## 5. 分步命令（出错时单独重跑）

都在仓库根目录的 Git Bash 里执行。`PP` 是 Unity 工程的绝对路径。

```bash
PP="$(pwd -W)/unity"
# 1 电视画面
bash tools/sets.sh Open '["stage"]'
bash tools/sets.sh SetupFilmBaker '[0,4634,1,1440,1080,"tv_raw"]'
unity command editor.playmode start --project-path "$PP"     # 等 unity/Capture/tv_raw 里有 4634 张 jpg
unity command editor.playmode stop --project-path "$PP"
# 2 电视开头的 AI 视频
python -P tools/tv_clips.py tv_raw tv
# 3 舞台镜头（可以只渲一部分，比如 "24,47,65"）
bash tools/play_shots.sh "8-80" cut 2560 1440 1 8
# 4 房间镜头
bash tools/sets.sh Open '["room"]'
bash tools/sets.sh RoomFilm '["1-7,46,52,74,81,82",8,1,2560,1440,"cut","tv"]' 3000
bash tools/sets.sh Open '["stage"]'
# 5 合成（没有 docs/字幕.json 就去掉 --captions）
python -P tools/finish_film.py cut deliver/film/成片.mp4 --crf 16 --captions docs/字幕.json
```

**快速预览**：
- 舞台单帧（编辑模式，最快）：`bash tools/sets.sh ShotStills '["24,47",0.5,1280,720,"stills"]'`。注意编辑模式下角色的蒙皮可能停在旧姿势，lin 的动作要以播放模式为准。
- 舞台低分辨率抽帧（播放模式）：`bash tools/play_shots.sh "24-30" quick 960 540 6 0`
- 只合成一段：`python -P tools/finish_film.py cut out.mp4 --from 24 --to 30 --crf 24`

## 6. 作品是怎么组织的（改动前先读）

| 要改什么 | 去哪里 | 说明 |
|---|---|---|
| 小节时间 | `unity/Assets/Stage/FilmBars.cs` | 86 个小节的起点和片尾时间，由 `docs/film_v5.json` 生成。所有动作都写成“第几小节第几拍”。 |
| 舞台上发生的一切 | `unity/Assets/Stage/FilmClock.cs`、`FilmV3.cs` | 布景升降、窗和灯泡、纸人、红纸、纸鸟、纸偶女孩、光束，都是时间的函数。纸的东西每秒 12 个位置，灯光连续变化。 |
| 灯和舞台状态 | `FilmClock.cs` 的 `BASE`、`STATE`、`TRACK` | 每种状态下每盏灯的倍数，以及什么时候切到哪种状态。灯的位置在 `unity/AgentScripts/src/40_lights_states.cs`。 |
| 机位 | `unity/Assets/Stage/FilmCams.cs` | `ShotCamera(n, t, cam)`：每个镜头一个分支，写明焦距、光圈、对焦点和运动。 |
| 镜头表 | `docs/film_v5.json` | 83 个镜头的起止帧、类型、焦距、接法。`FilmShots.cs` 由它生成。 |
| lin 的动作 | `unity/Data/key_song.bin` → `tools/lin_key_film.py` → `key_film.bin` | 全曲手 K 数据；影片专用的托鸟、放飞、正视、闭眼在 `lin_key_film.py` 里改，然后重新运行它。 |
| lin 的驱动 | `unity/Assets/MV/Scripts/`、`unity/Assets/Stage/StagePerformer.cs` | `SingDriver` 播放关键帧，`StagePerformer` 加影片要的视线和闭眼。 |
| 房间 | `unity/AgentScripts/src/60_room.cs`、`77_room_film.cs` | 房间机位、电视画面贴图、屏幕发光。 |
| 搭景（从零重建场景） | `unity/AgentScripts/src/10_*–36_*`、`79_v3.cs` | 入口 `Sets.Build`、`Sets.BuildRoom`、`Sets.V3Build`、`Sets.V3Art`、`Sets.LinSwap`。仓库里的场景已经搭好，一般不需要重建。 |
| 合成 | `tools/finish_film.py` | 接法（`HALF`）、撕裂（`TEAR`）、压暗（`GRADE`）、片名、片尾、响度。 |
| 字幕 | `tools/lyric_type.py` | 六种情绪排版，句子到风格的对应在 `STYLE_LINES`；lin 近景的字幕位置在 `FORCE`。 |
| 设计图纸 | `tools/make_blueprint.py` | 需要先渲出 `unity/Capture/cut5` 的帧（或改脚本里的 `CAP`），以及 Node.js、Playwright 和 Edge。 |

`tools/sets.sh <入口> '<JSON 参数>'` 会把 `unity/AgentScripts/src/*.cs` 拼成 `Sets.cs`，在正在运行的编辑器里执行 `Sets.<入口>`。改了 `unity/Assets/` 下的脚本之后，要先执行 `unity recompile --project-path "$PP"`，等状态回到 ready 再继续。

## 7. 常见问题

| 现象 | 原因与处理 |
|---|---|
| `unity command` 连不上 | 编辑器还在导入，或进了 Safe Mode（有编译错误）。看 `unity status`。 |
| 播放模式里帧数不涨 | 编辑器窗口不在前台，或者上一次的烘焙器还留在场景里。重新运行 `SetupShotBaker` 或 `SetupFilmBaker`，它们会先清掉旧的。 |
| 房间镜头里电视画面不对 | 电视画面目录（第 2 步的 `tv`）不完整，或者舞台场景里残留了 `ShotBaker`。重跑第 1、2 步。 |
| 合成时内存不足（ArrayMemoryError） | 关掉其他占内存的程序，或者分段合成（`--from/--to`）检查画面。成片仍然要整段合成一次，因为响度是整首歌一起标准化的。 |
| 字幕是方框 | 没跑 `tools/fetch_fonts.py`，或者系统里没有微软雅黑、Segoe UI。 |
| 整片节奏对不上 | `audio/song.wav` 的版本或时长不同（应为 193.09 秒）。 |
| GitHub 上的包下不下来 | 网络问题。请用户配置代理（`HTTPS_PROXY`），或在 Unity 的 Preferences 里设置代理。 |

    run: python -P tools/setup_paths.py
    verify: output contains "changed"

    verify: output ends with "failed: 0"
  - id: song
    verify: ffprobe -v error -show_entries format=duration -of csv=p=0 audio/song.wav  ->  193.04 .. 193.14
